# ADR-001: 주문 상태 전이 정책

## 상태

Accepted

## 배경

현재 주문은 `PENDING`, `CONFIRMED`, `PROCESSING`, `SHIPPED`, `DELIVERED`, `CANCELLED` 상태를 가진다. 주문 생성, 결제 확정, 운영자 배송 처리, 사용자 취소가 같은 enum을 공유하지만 허용 전이 정책은 코드와 문서에 고정되어 있지 않다.

상태 전이 규칙이 없으면 운영자 API 또는 내부 서비스 호출이 배송 완료 주문을 다시 처리 중으로 바꾸거나, 취소된 주문을 결제 확정 상태로 되돌리는 비정상 흐름을 만들 수 있다.

## 결정

주문 상태는 전진 흐름과 취소 흐름만 허용한다. 종결 상태인 `DELIVERED`, `CANCELLED`에서는 어떤 상태로도 전이하지 않는다.

| 현재 상태 | 허용 다음 상태 | 주체 | 설명 |
| --- | --- | --- | --- |
| `PENDING` | `CONFIRMED` | 결제 서비스 | 결제 성공 후 주문을 확정한다. |
| `PENDING` | `CANCELLED` | 사용자, 운영자 | 결제 전 사용자 취소 또는 운영자 취소를 허용한다. |
| `CONFIRMED` | `PROCESSING` | 운영자 | 결제 확정 주문의 출고 준비를 시작한다. |
| `CONFIRMED` | `CANCELLED` | 사용자, 운영자 | 출고 전 취소를 허용한다. |
| `PROCESSING` | `SHIPPED` | 운영자 | 출고가 완료되어 배송 중 상태로 바꾼다. |
| `PROCESSING` | `CANCELLED` | 운영자 | 출고 준비 중 운영자 취소만 허용한다. |
| `SHIPPED` | `DELIVERED` | 운영자 | 배송 완료 처리를 한다. |
| `DELIVERED` | 없음 | 없음 | 배송 완료는 종결 상태다. |
| `CANCELLED` | 없음 | 없음 | 취소는 종결 상태다. |

## 제한 상태 정책

- `SHIPPED` 상태에서는 사용자 취소와 운영자 취소를 모두 거부한다. 이후 반품과 환불은 별도 상태 모델에서 다룬다.
- `DELIVERED` 상태에서는 모든 주문 상태 변경을 거부한다.
- `CANCELLED` 상태에서는 결제 확정, 배송 처리, 재취소를 포함한 모든 상태 변경을 거부한다.
- 같은 상태로의 반복 변경은 멱등 성공으로 처리하지 않고 잘못된 전이로 본다. 재시도 멱등성은 호출 계층에서 idempotency key 또는 처리 이력으로 해결한다.

## 적용 범위

- `Order.updateStatus`는 이 전이표를 기준으로 검증해야 한다.
- `OrderService.markOrderConfirmed`는 `PENDING -> CONFIRMED`만 허용해야 한다.
- `OrderService.cancelOrder`는 `PENDING`, `CONFIRMED`에서 사용자 취소를 허용하고, 운영자 취소가 필요한 경우 별도 메서드 또는 요청 주체 구분을 추가해야 한다.
- 운영자 상태 변경 API는 임의 enum 변경이 아니라 전이표에 있는 다음 상태만 허용해야 한다.

## 결과

이 정책은 주문 상태를 단순한 전진형 상태 머신으로 고정한다. 부분 취소, 반품, 부분 환불, 배송 후 환불은 현재 주문 전체 상태에 억지로 넣지 않고 Phase 3의 주문 라인 상태와 환불 정책에서 별도로 설계한다.
